## Recovery

Before the migration, return to the captured compatible functions and frontend after reconciling leases. After the migration, keep maintenance/frozen and recover **forward** with compatible functions; do not restore the old frontend alone or lower the stale-client revision. A bad frontend can use the captured compatible Production deployment while the matching backend remains in place. A bad live checkout configuration should close the public gate, keep the live webhook able to fulfill already completed payments, and retain the sandbox webhook. For provider or webhook failure, reconcile signed event and transaction IDs before reopening purchases. Never delete an intent or payment to force a gate, and never overwrite production from a pre-failure backup after intervening customer writes or payments. The frozen backup is a recovery reference, not an automatic rollback command.
