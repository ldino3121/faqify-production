# Gemini reliability and model replacement

`analyze-content` uses `GEMINI_API_KEY` (or the existing legacy key aliases) in the Edge Function environment. The reviewed primary model is `gemini-2.5-flash`; the reviewed fallback is `gemini-2.5-flash-lite`. Optional server-side `GEMINI_PRIMARY_MODEL` and `GEMINI_FALLBACK_MODEL` select between this pair only. Neither value is a browser variable. Do not add an unreviewed model ID to the allowlist or use a `latest` alias.

Each model receives at most two attempts with an 18-second per-attempt timeout. Transient overload, temporary rate limits, network failures and timeouts can retry with exponential backoff, jitter and a provider retry hint when it fits the deadline. An explicit model-unavailable response can use the reviewed fallback. Authentication, exhausted daily quota, generic 404, safety block and invalid output stop without a blind retry. The provider phase has a 75-second budget and the request has a 120-second ceiling, leaving time within Supabase's 150-second idle limit to release the generation reservation. Failed generation does not charge credits; a successful atomic save charges eligible pairs once.

The admin-only `analyze-content` request `{ "action": "model_health" }` makes authenticated Google `models.get` calls with the deployed project key. It returns model IDs, availability and HTTP status only. It neither generates FAQs nor reserves credits. Check this after deployment and before any model change; a public documentation listing alone does not prove availability for this project.

Before replacing a model, review Google's current model and pricing documentation, compare input/output token limits, structured JSON support, price per token and expected FAQ quality, then obtain approval for any material cost or quality change. Add the exact approved ID to the allowlist and update configuration in a reviewed rollout. Exercise the fault-injection tests and a synthetic count/shortfall matrix, then run an approved-account hosted generation and inspect the saved pairs and credit allocation. Change one model at a time. Roll back by restoring the reviewed pair in Edge Function configuration or redeploying the previous function version; preserve the current Gemini key.

The function emits one `gemini_attempt` metric per attempt: model, attempt number, latency, HTTP status, error category and fallback flag. It does not log source material, prompt text, credentials or raw provider output. In Supabase Logs, filter `analyze-content` for `gemini_attempt`, `analyze_content_failed` and `generation_reservation_release_failed`. Investigate repeated fallback use, spikes in rate limiting or invalid output, any authentication/model-unavailable result, and every reservation-release failure. A scheduled check can use the existing Supabase/GitHub infrastructure to call the authenticated admin health action; do not publish its credentials or add an external monitoring service without approval.
